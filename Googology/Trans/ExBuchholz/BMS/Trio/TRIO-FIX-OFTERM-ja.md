# パッチ "ofTerm": 項 ψ_a(b) の読み方

ファイル: [TrioFixOfTerm.lean](TrioFixOfTerm.lean) (パッチ),
[TrioFixOfTermSheet.lean](TrioFixOfTermSheet.lean) (検査)。
パッチは `TrioRulesAll` の上にのる。**ビルダーの定義は 1 つも変えない**。
変えるのは、拡張ブーフホルツ表記の項を規則の標準形に読む部分 (`TrioRules.ofTerm`) だけ。

## 問題

`ofTerm` は b ≠ 0 の ψ_a(b) をすべて 1 つのアトム ψ_a(b) と読む。
規則のアトムは x ↦ ω^x の不動点である
([アルゴリズムのページ](https://github.com/koteitan/trio/blob/main/ebp2bms/algorithm/2/README-en.md) の "Atoms")。
[シート](https://github.com/koteitan/trio/blob/main/tools/omega_alpha_rows.tsv) の ψ アトムは、
どれも引数の項がすべて Ω_{a+1} 以上である。
なので ψ_0(Ω+1) = ε₀·ω がアトム `psi(W+1)` と読まれていた。
規則はこれをラベル ε₀^{ε₀^ω} (2163 行) と同じに並べる。ε₀·ω (2158 行) ではない。

## 読み方 (変更 1)

引数を分ける: b = b_hi + b_lo。

- b_hi = c > a である項 ψ_c(d) (どれも Ω_{a+1} 以上)
- b_lo = c ≤ a である項 ψ_c(d) (どれも Ω_{a+1} 未満)

すると

    ψ_a(b_hi + b_lo) = ω^(P + b_lo)
    P = ψ_a(b_hi)  (b_hi ≠ 0 のとき)
    P = Ω_a        (b_hi = 0, a ≠ 0 のとき)
    P = 0          (b_hi = 0, a = 0 のとき)

b_lo = 0 なら前と同じアトム。a = 0, b_hi = 0 なら前と同じ ω^b。
例:

| 項 | 値 | シートのラベル |
|---|---|---|
| ψ_0(Ω+1) | ω^(ε₀+1) = ε₀·ω | `psi(W)*w` |
| ψ_0(Ω+ψ_0(Ω)) | ω^(ε₀·2) = ε₀^2 | `psi(W)^2` |
| ψ_1(1) | ω^(Ω+1) = Ω·ω | `W*w` |
| ψ_1(ψ_0(Ω)) | ω^(Ω+ε₀) = Ω·ε₀ | `W*psi(W)` |
| ψ_1(Ω) | ω^(Ω·2) = Ω^2 | `W^2` |

Lean で証明したこと: `val_psi_Omega_add`: t < ε₁ なら ψ_0(Ω+t) = ε₀·ω^t = ω^(ε₀+t)
(`Ord.psi_Omega_add_eq` から)。一般の等式 (ψ_a は Ω_{a+1} 未満の部分で連続) は証明していない。

## 変更 2: 無限の添字

シートは無限のレベル c の崩壊を基数 Ω_{c+1} で書く:
`psi_W_(w+1)(W_(w+1))` = ψ_ω(Ω_{ω+1})、`psi_W_(W+1)(W_(W+1))` = ψ_Ω(Ω_{Ω+1})。
添字の形 `psi_c` は有限の c にだけ使う。
`ofTerm` はどの c でも `psi_c` と書いていた。c = Ω だと、これはプログラムでは基数の形
ψ_{Ω_1}、つまり Ω より下の崩壊になる。そこで `psiAtom` は無限の c を `psi_{Ω_{c+1}}` と書く。
変更 2 だけ外すこともできる (`psiAtom cf X := .psi cf X`)。

## マージのために

- `ofTermFix` を `TrioRules.ofTerm` の本体と置き換える。
- `trioMatrixLFix α = trioRuleMatrixAll (ofTermFix α)` を `trioMatrixL` と置き換える。
- `ofTermFix_allNil`: ε₀ 未満では何も変わらない (証明済み)。

変更 1 を ψ_0 だけにした版は、42 個のラベルのうち 21 個しか合わない。

smallFrag 6 では、展開は 2 つの写像を区別しない (シートの外で実行):
0 でない 448 個の極限 α と n ≤ 2 について、M(α) の BMS 展開のある段 m ≤ 6 が
M(α[n]) (Buchholz の基本列 `fs`/`idx`) に届き、どの段も M(α) より下にある。
2 つの写像とも 448 個すべてで通る。
だから読み方を決めるのは、シートの行と (ε₀·ω)[n] = ε₀·(n+1) である。

標準形 (yaBMS `bms -s`、Lean の外):
smallFrag 6 新: 610 個すべて。ψ 7 個以下 新: 2397 個中 2396 個 (下の β 以外)。
添字 0,1,2: どちらの読みでも 483 個中 481 個。α < Ω_2: 524 個すべて。
添字 0,1,ω: 新は 527 個中 30 個が非標準、古は 537 個中 61 個。
添字 0,1,Ω: 新は 512 個中 59 個、古は 291 個中 46 個。

## まだ間違っているところ

1. **TrioTree の定理は古い写像についての定理。** 書かれたとおりには今も正しい
   (TrioTreeRules.lean の `trioMatrixL_eq_trioE`, `trioMatrixL_std`,
   `trioMatrixL_lt_iff`, `trioMatrixL_injective`)。
   古い写像を新しい写像に置き換えると、順序の定理は偽になる。
   Lean で証明済み (`trioMatrixLFix_order_fails`, `not_trioMatrixLFix_lt_iff`):

       α = ψ_0(ψ_1(ψ_0(Ω)))              = ε_{ε₀}
       β = ψ_0(ψ_1(ψ_0(Ω + ψ_0(Ω+1))))   = ε_{ε₀^{ε₀^ω}}
       α, β は標準形、< Ω、添字 0/1、dep ≤ 200、α < β
       新: M(β) < M(α)        古: M(α) < M(β)

   新しい写像は smallFrag 6 (610 項、`#guard`) では順序を保つ。
   ψ 7 個では失敗 (127 組) はすべて β を含む。
   標準形: smallFrag 6 はすべて、ψ 7 個では 2397 個中 2396 個 (β だけ非標準。
   yaBMS、この報告のために再実行)。Lean では証明していない。
2. **ψ 7 個までのただ 1 つの失敗はビルダーの欠陥。**
   β = ψ_0(ψ_1(ψ_0(Ω+ψ_0(Ω+1)))) = ψ_0(Ω·ε₀^{ε₀^ω})、ラベル `psi(W*psi(W)^psi(W)^w)`。
   行列 `(0,0,0)(1,1,1)(2,1,1)(3,0,0)(4,1,0)(5,0,0)(6,0,0)(7,1,0)(7,0,0)`
   は非標準で、ε_{ε₀} = `psi(W*psi(W))` の行列より下にある。
   ビルダーは ω^{ε₀·ω} を ψ_0(ψ_0(Ω+1)) の木として書く。
   正しい木は ψ_0(Ω+ψ_0(Ω+1))。規則 1 の `strip` は、指数の先頭が ψ アトムのときしか
   崩壊を戻さない。ω^{ε₀+1} の先頭は ω^{…} である。
   β の行列を項の木に取り替えると、127 個の食い違いは 0 になる。
   シートのどの行もこの場合に届かない。
3. **大きい添字。** 添字 0,1,ω では新しい写像に 63 個の順序の食い違いがある (古: 0)。
   どれも、両方にシートの行がある 2 つの順序数の間ではない。
   シートの外のビルダーの欠陥で、古い読みはこれらの項をアトムと読んでいたので届かなかった。
   添字 0,1,Ω では新しい写像に 137 個の食い違いと 29 個の衝突がある (古: 58277 個と 2743 個)。
   この 137 個はシートと照らし合わせていない。
