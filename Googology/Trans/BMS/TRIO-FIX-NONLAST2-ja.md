# Fix G・Fix M・変更 1 を狭める

[`TrioFixNonLastOther.lean`](TrioFixNonLastOther.lean)（[koteitan/trio](https://github.com/koteitan/trio)
の規則 1〜10 に Fix A〜E, N, G, M と変更 1〜4 を入れたもの）の上に重ねる別パッチ。コードは
[`TrioFixNonLastOther2.lean`](TrioFixNonLastOther2.lean)、検査は
[`TrioFixNonLastOther2Sheet.lean`](TrioFixNonLastOther2Sheet.lean) と重いシート 2 つ
（`TrioFixNonLastOther2SheetHeavy1`, `…Heavy2`、ライブラリ `GoogologySheets` 向け）にある。
マージするときは、`placeUnitsX` と `blockX` の中で `spentX` を `spentX2` に、`fixXNeeded` を
`fixXNeeded2` に、`fixX` を `fixX2` に置き換える。

## 誤り

`TrioFixNonLastOther` は、tower でない regime で最後でない葉を直す。較正した 5 つの家族では
正しいが、レビューで家族の外に、パッチ前（`TrioRulesAll`）は順序が合っていて、パッチ後に
ずれる組が見つかった。

- Fix M（変更 3）、regime `Ω_2`, `Ω_3`, `Ω_4`, `Ω+1`, `Ω_{Ω+1}`:
  `M(Ω_{Ω_2}+Ω_ω+Ω) < M(Ω_{Ω_2}+Ω+ω)`。パッチ後の行列は標準形でない。
- Fix G（変更 2）、regime `Ω_{ω·2}`, `Ω_{ω+2}`, `Ω_{Ω_ω}`:
  `M(Ω_{Ω_{ω·2}}+Ω_{ω·2}) > M(Ω_{Ω_{ω·2}}+Ω_Ω+Ω)` ほか 2 組。
- 変更 1、regime `Ω_{ω^2}`: `M(Ω_{Ω_{ω^2}}+Ω_{ω·2}) < M(Ω_{Ω_{ω^2}}+Ω_ω+Ω)`。

`M(α)` は `ψ_0(Ω_α)` の行列。regime `r` は `Ω_r ≤ α < Ω_{r+1}` となるレベル。

## 原因

- **葉が下の top と同じ。** Fix M と Fix G は、レベル `p` の葉のあとにコピーを置く。この
  コピーが役に立つのは、`p` の葉が下のレベルの葉と違うときだけである。`r = Ω_2` では `ω`
  の葉の 1 行目の値は `1` で、top `1` の葉と同じ（top `2` の葉 `2` より下）。`r = Ω_{ω+2}`
  では `Ω` の葉の値は `2` で、top `ω+1` と同じ。このときコピーは、下のレベルの普通の
  続きより下に来る。
- **upgrade が途中で止まる。** `p = Ω` の葉は、葉が `1` を指す sub-unit で upgrade される。
  `r = Ω_{ω·2}`, `Ω_{ω·3}`, `Ω_{ω+2}` にはそういう sub-unit がない。そのため `Ω` の葉は、
  印のある下のレベル（`r = Ω_{ω·3}` では `ω·2`）の葉のままになり、コピーはそのレベルの印
  より下から始まる（`(3,2,0)` 対 `(3,2,1)`）。
- **変更 1 が、必要な storey を消す。** 変更 1 は、非可算の regime すべてで規則 6（`spent`）
  を切る。`y = 1` の葉のあとに置く storey が標準形でないからである。しかし `r = Ω_{ω·2}` では
  regime の葉は `y = 2` にあり、そこでは storey が順序を保っている。

## 変更

記法: `tops r = chainG r`。`N(v)` は、今の状態で `v` を指す葉の 1 行目の値
（`leafNameOrYN`）。`suffixOf (chainBase u) ≠ []` のとき、レベル `u` は「印つき」という。

1. **変更 1′**（`spentX2`）。非可算の regime で規則 6 を切るのは、`keepSpent` が偽のとき
   だけにする。

       keepSpent ⇔ leafY r ≠ 1 ∨ (p が印つき ∧ p ∉ tops r)

2. **Fix G′**（`fixGNeeded2`）:

       fixGNeeded2 = fixGNeeded ∧ leafApart ∧ upgradeFull
       leafApart   ⇔ ∀ t ∈ tops r, t < p → N(t) ≠ N(p)
       upgradeFull ⇔ 最後の葉の upgrade が p の Ω 連鎖の終わりまで届く

3. **Fix M′**（`fixMNeeded2`）:

       fixMNeeded2 = fixMNeeded ∧ (r が tower ∨ leafApart)

4. `fixX2` は、`fixMNeeded2` のとき Fix M′、そうでなければ Fix N（Fix G′ も兼ねる）。

変更 4（持ち上げた葉）とほかの部分は変えない。

## 未解決

- **葉を共有したあとの組が、まだ壊れている。** `Ω_{Ω_{ω+1}}`, `Ω_{Ω_{ω+2}}`, `Ω_{Ω_{Ω_ω}}`,
  `Ω_{Ω_{ω^2+1}}` の後で、`TrioRulesAll` では順序が合っていた組が、それぞれ 6, 52, 24, 22 組
  まだずれている。どれも、下の top と葉を共有するレベルの葉のあとで起きる（例:
  `γ+Ω_Ω+…` 対 `γ+Ω_{ω+1}+…`）。Fix G′ はその葉には手を出さなくなったが、あとの Fix G′
  のコピーや持ち上げた葉（変更 4）が、組の順序をずらす。そういう葉のあとの修正をすべて
  切る案も試した。`6, 52, 24 → 0, 0, 13` になるが、`Ω_{Ω_{ω·2}}` の後でずれが 2,626 から
  2,781 に増える。だから入れていない。
- **`Ω_{Ω_{ω^2}}`:** `γ = Ω_Ω`, `Ω_{ω^2}` で `M(γ+Ω_ω) > M(γ+Ω_ω+x)`（8 組）。最後の葉の版には
  印 `(3,2,1)` がつき、規則 6 が葉のあとに置く storey はそれより下に来る。
- **規則 6 が戻った所で行列が大きい。** `Ω_{Ω_{ω·2}}` の後では、規則 6 の storey と変更 4 の
  持ち上げたコピーが重なり、行列が最大 656 列になる（`Ω_{Ω_{ω·2}}+Ω_{ω·2}+Ω_2+Ω_2` は
  296 列）。221 個のうち 117 個が標準形でない。`TrioRulesAll` では 124 個（最大 74 列）、
  `TrioFixNonLastOther` では 20 個。117 個のうち、`TrioRulesAll` で標準形だったものは 1 つも
  ない。これらのラベルは Lean で 1 つ数分かかる。そのため、この regime のシートの家族からは
  `Ω_2` を外した。
- **原因の最後の葉は、この項目の外。** `γ = Ω_{Ω_{ω+1}}`, `Ω_{Ω_{ω+2}}` で
  `M(γ+Ω_Ω) = M(γ+Ω_{ω+1})`。`γ = Ω_{Ω_{ω^2}}` で `M(γ+Ω_ω) = M(γ+Ω_{ω·2})`。どちらも
  `TrioRulesAll` ですでに成り立つ。`Ω_{Ω_2}` の後では、`Ω_ω` の葉は `Ω` の葉に印 `(1,1,1)`
  をつけたもので、その行列は標準形でない。
- [`TrioFixNonLastOther.lean`](TrioFixNonLastOther.lean) の「未解決」はそのまま残る。ただし最後の
  項目（レビューで見つかった後退）は、このパッチで答えた。
