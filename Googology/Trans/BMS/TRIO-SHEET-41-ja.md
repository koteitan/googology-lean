# トリオのシートと規則 1–10 が食い違う 41 行

`TrioRules.lean` は [koteitan/trio](https://github.com/koteitan/trio) の規則 1–10
（[アルゴリズムのページ](https://github.com/koteitan/trio/blob/main/ebp2bms/algorithm/2/README-en.md)）
を書き写したもの。シート
[`tools/omega_alpha_rows.tsv`](https://github.com/koteitan/trio/blob/main/tools/omega_alpha_rows.tsv)
の標準形の行は 785 あり、そのうち 744 行で規則とシートが一致する。残りの 41 行では、規則（と参照実装
[`tools/probe_eps_range.py`](https://github.com/koteitan/trio/blob/main/tools/probe_eps_range.py)）
がシートと違う行列を出す。`TrioRulesSheet.lean` はこの 41 行を `≠` の guard で確かめている。

このノートでは、41 行のそれぞれについてどちらが正しいかを決める。見るのは、どちらの行列が標準形か、どちらが `α` の順序を保つか、の 2 点。

**41 行のどれも `TrioRules.lean` の書き写し間違いではない。** どの行でも、Lean の書き写しは参照実装と同じ行列を出す。規則が間違っている行では、間違いは規則そのものにある。

裏付けに使った有限の検査は [`TrioSheet41.lean`](TrioSheet41.lean) にある。どれも `#guard` で、較正であって定理ではない。

## 結果

まとめると、規則が正しいのは 17 行、シートが正しいのは 22 行。

アルゴリズムのページは同じ 41 行を別の形で分けている。規則が正しい 4 行、シートが正しい 3 行、決まらない 34 行。このノートでは、3552 を「シートが正しい」から L に移す（ラベルの誤記なので）。3480 は「シートが正しい」から O に移す。

全体の検算: 一致する 744 行と、残りの 39 行（3439 と 3480 は外す）それぞれについてここで選んだ行列（ラベルは直したもの）を並べる。これで 783 個の行列になる。その全 306,153 組で、行列の順序はラベルの順序（`cmp_ord`）と同じになり、同じ行列を持つラベルの組もない。さらに L の 9 行の書かれたラベルに対する規則の行列を足すと、792 個の行列、313,236 組になる。このときの例外は、行 3552 と 4369 の誤ったラベルに対する規則の出力の 2 つだけ。この 2 つは規則そのものの欠陥で、「そのほかに見つかったこと」に書いた。

## 決め方

1. **標準形。** yaBMS の `bms -s`（[koteitan/yaBMS](https://github.com/koteitan/yaBMS)）で調べる。シートの 41 個の行列はすべて標準形。規則の行列は、3480、3492、3552 の 3 行を除いて標準形。
2. **順序。** 標準形どうしの BMS の順序は、列の辞書式順序（yaBMS の `bms -c`、`TrioMono.lean` の順序）。候補の行列を、一致する 744 行すべてと比べる。どの行に対しても、行列はラベルと同じ側にないといけない。ラベルどうしは参照実装の順序数比較 `cmp_ord` で比べる。一致する 744 行では、`cmp_ord` と行列の順序は 276,396 組すべてで合う。
3. **衝突。** 違う 2 つの順序数に同じ行列が出るなら、少なくとも一方は間違い。
4. **展開。** `M[n]` は yaBMS か `expandRL 3 n` で計算する。`expandRL` が BM4 の展開であることは `EntriesR.lean` で証明されている。どちらも悪い部分を `n + 1` 個並べる。一致する行を展開すると、問題の行の行列が出ることがある。展開がどう振る舞うかは一致する行で較正する。例えば `u = 1, ω, ω²` で `(Ω_{Ω_u}·ω)[1] = Ω_{Ω_u} + Ω_{u+1}` となる。
5. **形。** 同じ種類の一致する行を見ると、項がどんな形で書かれるかがわかる。例: 末尾の `+1` は `z = 0` の列、末尾の `·ω` は `z = 1` の桁、`X^X` は兄弟の葉 2 つで終わる。
6. **`ε₀` 未満。** ここでは規則は `omegaIndexMatrix` そのもの。この写像が標準形を出すことと順序を保つことは、`TrioStd.lean` と `TrioMono.lean` で証明されている。

### L: ラベルの誤記（9 行）

どの行でも、シートの行列は、直したラベルに対して規則が出す行列とちょうど同じ。直したラベルは両隣の一致する行の間に来るので、シートの行の順番とも合う。どの行にも、文字の上での根拠がある。

- 4 つのラベルは、シートの別の行にも出てくる（2131/2133、2532/2538、3777/3778、4384/4309）。
- 2723 は 2724 と同じラベル。
- 2 つの元のラベルは括弧が 1 つ足りない（3452、4369）。スクリプト
  [`normalize_sheet.py`](https://github.com/koteitan/trio/blob/main/tools/normalize_sheet.py)
  は足りない `)` を末尾に足すが、これは違う位置。
- 2113 は、両隣から見て `·2` のところが `·3` になっている。
- 3552 は、シート上の位置から見て `ω+1` のところが `Ω+1` になっている。

### N: シートの行列が隣の順序数のもの（5 行）

どの行でも、書かれたラベル自体はありうるもので、それに対する規則の行列は、同じ種類の一致する行と同じ形をしている。シートの行列は、近くの別の順序数に対する規則の行列になっている。間違いがラベルにあるのか行列にあるのかは、ここでは決められない。どちらにしても、シートの行はそのラベルの `M` を与えていない。

### R: 規則が正しく、シートの行列の正体がわからない（3 行）

- **2133。** `ε₀` 未満では規則は `omegaIndexMatrix` で、標準形を出すことと順序を保つことが証明されている。`M(ω^ω+ω²)[1]` でも同じ行列になる。
- **3923。** 一致する `ψ_{Ω_u}(Ω_u)` の 14 行はすべて規則 9 に従う。最後の葉を 1 段下げ、1 段上の列を続ける。シートの行はそうなっていない。
- **3551** は根拠が弱い。どちらの行列も標準形で、順序も合う。規則は `Ω_ω` の印を崩壊の引数の中、写した添字が始まる列の位置に書く。一致する 2180（`ψ_0(Ω_ω²)`）、2181、2552 も同じ書き方をする。シートは `(1,1,1)` を最上段に置く。この種類の一致する行で、そう書くものはない。

### S-o: 規則の行列の順序が合わない（12 行）

どの行でも、規則の行列は少なくとも 1 つの一致する行と順序が合わない。シートの行列は標準形で、一致する両隣のちょうど間に来る。3 つのまとまりに分かれる。

- **添字が `ψ_{Ω_u}(Ω_u)` や `ψ_1(Ω_2)` の形の行**（4508、4628、4674、4762、4769）。規則の行列は、土台 `M(Ω_{Ω_…})` から最後の列を落としたもの。`W_(W^W)` などの行より下に来てしまい、本来の位置よりずっと下になる。
- **`Ω_{Ω_ω}` の系列の印**（4609、4613、4618）。シートは `Ω_ω` を「`Ω` の形の後に印 `(1,1,1)`」と書く。これは `M(Ω_{Ω_ω}) = M(Ω_Ω) ++ (1,1,1)` と同じ規則で、`M(Ω_{Ω_ω})[0] = M(Ω_Ω)` と `M(Ω_{Ω_ω})[1] = M(Ω_{Ω_2})` で確かめられる。
- **`Ω_{Ω+1}` の演算**（4488、4490、4491）と **3492**。

### S-c: 規則が 2 つの順序数に同じ行列を出す（10 行）

規則は次の組に同じ行列を出す。

- 4744 と 4746、4745 と 4747、4750 と 4752、4751 と 4753（`Ω_{Ω_Ω}` の系列）
- 4667 と `Ω_{Ω_{ω²}}+Ω_{ω²}`
- 4497 と `Ω_{Ω+ω}·Ω`

これらの行について、シートの行列はどれも違っていて、順序も合う。一部は別の根拠でも確かめられる。

- **4745** は展開で確かめられる。一致する行では `u = 1, ω, ω²` で `(Ω_{Ω_u}·ω)[1] = Ω_{Ω_u}+Ω_{u+1}` が成り立つ。`u = Ω` ではこれがシートの `Ω_{Ω_Ω}+Ω_{Ω+1}` の行列を出す。つまりこの範囲では、番地 `y = 3` が表すのは `Ω_{Ω+1}` で、規則の読みの `Ω_3` ではない。
- **4744 と 4750** は形で確かめられる。4464、4465、4761 と同じ `+Ω_Ω` の末尾を持つ。
- **4497** は形で確かめられる。末尾に `·ω` の桁がある。
- **4667** は形で確かめられる。4613 と同じ形。

4746、4747、4752、4753 の根拠は、シートの行列がほかと矛盾しないことと、規則の行列が衝突していることだけ。この 4 行は単独では確かめていない。

### X: 行 3439 は `ψ_0(Ω_α)` の行ではない

元のラベルは `psi(W_(W_w*w0*W_W_w+W_(W_w*w))`。`0` は `)` の打ち間違いで、正しいラベルは `ψ_0(Ω_{Ω_ω·ω}·Ω_{Ω_ω} + Ω_{Ω_ω·ω})`。これはシート全体の中での位置、行 3438 と 3440 の間とも合う。行列も両者の間に来る。抜き出しのときに、純粋な `ψ_0(Ω_α)` の行と取り違えられた。規則は `w0` を `ω·0 = 0` と読み、`M(Ω_{Ω_ω·ω})` を出した。これは行 4625 の行列。

### O: 行 3480 は未決

`Ω_ω·Ω+Ω_3` に対する規則の行列は、素の葉 `(8,3,0)` で終わる。この行列は標準形でない。アルゴリズムのページも、この文脈には深さ 3 の番地がないと書いている。シートの行列は標準形で順序も合うが、規則でいう `Ω_ω·Ω+Ω·ω`、つまりもっと小さい順序数の行列になっている。すぐ後のシートの 2 行（3481、3482）は標準形でない。このあたりのシートは当てにならず、`M(Ω_ω·Ω+Ω_3)` はまだわからない。

## そのほかに見つかったこと

- **3552 の書かれたままのラベル。** `ψ_{Ω_{Ω+1}}(Ω_{ψ_{Ω_{ω+1}}(Ω_{ω+1})})` に対する規則の行列は標準形でなく、`M(ψ_{Ω_{Ω+1}}(Ω_{Ω_2}))` より上に来る。規則は、シートにないこの順序数で破綻する。
- **`ω^3·Ω` が正規化されない。** 参照実装と `TrioRules.lean` の `mul` は、指数 `ω^(3+Ω)` を原子 `.W 1` ではなく `.o [(.W 1, 1)]` として作る。`ω^原子 = 原子` の規則が使われていない。そのため `cmp_ord` は `Ω_{ω^3·Ω}` と `Ω_Ω` を等しいとするのに、規則は 2 つに違う行列を出す（4369 の書かれたままのラベル）。直し方は、指数を作るときに、`addExp e1 e` が係数 1 の原子 1 つならその原子をそのまま使うこと。参照実装と `TrioRules.lean` の両方を直して、同じ動きに保つ必要がある。
