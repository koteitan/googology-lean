# 修正 S: `Ω_ω·Ω+Ω_2` から `Ω_ω·Ω·2` までの区間

[TRIO-ROW-3480-ja.md](TRIO-ROW-3480-ja.md) は、[koteitan/trio](https://github.com/koteitan/trio) の
シート [`tools/omega_alpha_rows.tsv`](https://github.com/koteitan/trio/blob/main/tools/omega_alpha_rows.tsv)
の行 3480 を決めた。`β = Ω_ω·Ω` と書くと、`β+Ω_3` の行列は `c2` になる。同じノートによると、規則は
`β+Ω_2` から `β·2` までの区間全体でまちがっている。このノートは、その行列を規則に出させるパッチ
「修正 S」を説明する。

- コード: [`TrioFixStretch.lean`](TrioFixStretch.lean)。[`TrioRulesAll.lean`](TrioRulesAll.lean)
  （規則 1–10 に修正 A–E と N を入れたもの）の上にのせる、別のパッチ。
- チェック: [`TrioFixStretchSheet.lean`](TrioFixStretchSheet.lean)。
  [`TrioRulesAllSheet.lean`](TrioRulesAllSheet.lean) のチェックをすべてやり直し、修正 S 自身のチェックを
  足す。

## 区間の作られ方

`α = β + …` の体制（regime）は可算な `r = ω`。つまり `α ≥ Ω_ω` で、`r` 自身は可算。`β` のあとの単位は
*敷かれる*。`β` の最後の葉 `(8,1,0)` は `Ω` を指し、`leafY 1 = leafY ω` だからだ。そこで builder は、
その単位の前に階（storey）を 1 つ敷く。この階が `w1` の `(1,1,0)…(6,1,0)` の部分。

この階の中では、葉の値 `L = leafY r + 1 = 2` が、土台 `M(Ω_ω)` での値 `1` と同じ役をする。

- 葉 `(8,2,0)` は `Ω_2` を指す。
- 葉 `(8,2,0)` に印 `(2,2,1)` がつくと `Ω_ω` を指す。
- `Ω_3`、`Ω_4`、… は、それぞれ階がもう 1 つずつ要る。

新しい階は、前の階を BMS 自身がコピーしたもの。このコピーは
[`TrioRulesNonLast.lean`](TrioRulesNonLast.lean) の `blift` が作る。どの列も 1 つ右へずれる。上へ 1 つ
上がるのは、行 1 の祖先をたどって階の根に届く列だけ。列 `(6,1,0)` の行 1 の親は根 `(0,0,0)` なので、
`(7,1,0)` になる。ただ全体を持ち上げる `laySt` だと `(7,2,0)` になり、標準形でなくなる。

## 変更点

修正 S は、可算な体制 `r` の中で、*階の中の*単位にだけはたらく。単位が階の中にあるとは、その単位が
敷かれたか、`α` の前の単位が敷かれたか、その前に S3 のコピーが敷かれたこと。ほかは `TrioRulesAll`
のままで、変えない。

- **S1、葉の名前。** `r` を指す単位の葉は `L` をとる。前は錨の高さ `Ctx.level` だった。`v < r` で
  `leafY v > L` の `v` を指す単位の葉も `L` をとる。コピーの cap を指す葉は、コピーの値のまま。
- **S2、深い高さ。** 値 `L` の葉が `p < r`（`leafY p > L`）を指す桁のあと、builder は持ち上げたコピーを
  `leafY p - L` 個つなげる。どのコピーも葉まで持ち上げる。だから `M(β+Ω_{2+k})` は、`w2` のあとに
  コピーが `k` 個並んだもの。
- **S3、あとに続きがある葉。** 次の桁、次の単位、次の項の前に、builder は修正 N の持ち上げたコピーを
  葉をそのままにして敷く（`fixN`）ことがある。敷くのは、最後の列が値 `> leafY r` の葉で、
  `p < r` を指し、`p` に印がなく、前のコピーの cap でもないとき。そのあと `p` が cap になり、残りは
  コピーの上に続く。TRIO-ROW-3480-ja.md が `β+Ω_2+1`、`β+Ω_2·ω`、`β+Ω_2·Ω`、`β+Ω_2^2` に
  見つけた形がこれ。
- **S5、2 つ目の階を敷かない。** 階の中の単位では、使い切った葉があっても新しい階を敷かない。BMS も
  同じ結果を出す。
  - `M(β+Ω·ω)[1] = w1 ++ (7,4,0)(8,5,1)(9,5,1)(10,1,0)`
  - `M(β·ω)[2] = b1 ++ (7,4,0)(8,5,1)(9,5,1)(10,2,0)(9,5,1)(10,1,0)`

  どちらも同じ階の中に続いている。
- 階の中の単位では、**修正 D と、単位の終わりに敷く階を使わない**。S1–S3 がその役をする。階の外では
  どちらも変わらないので、行 3492 `Ω_ω·Ω_2·ω` は修正 D のまま。

マージのために: `placeUnitsS` は `placeUnitsN` に `-- Fix S` の行を入れたもの、`blockS` は `blockN`
に `-- Fix S` の行を入れたもの。`MstepS` は、`MstepAll` の `placeUnitsN` と `blockN` をこの 2 つに
置きかえたもの。`ψ` と `Ω_v` の分岐は変わらない（`MstepS_eq_MstepAll_of_ne`）。

## まだまちがっているところ

- **`Ω_ω·Ω^2 + …`。** ここで修正 S は 19 個の行列を変えるが、標準形でないまま（前も標準形でなかった）。
  因子が 1 つ上の、同じ種類の階で、区間の外にある。
- **`Ω_{ω^2}·Ω+Ω_ω·2`** は標準形でないまま。ここでは葉が印つきの高さ（`Ω_ω`）を指していて、S3 は
  それをあつかわない。
- **`Ω_ω` の族。** TRIO-ROW-3480-ja.md のとおり、`M(Ω_ω+Ω_2)` の葉 `(8,2,0)` のあとに続くものは
  標準形でないまま。たとえば `Ω_ω+Ω_2+1`、`Ω_ω+Ω_2·ω`、`Ω_ω+Ω_2^ω`、`Ω_ω+Ω_3+1`。そこには敷かれた
  単位がないので、修正 S はさわらない。ノートによれば、`M(Ω_ω+Ω_2)` の上に同じ 4 つの形を作ると標準形に
  なる。だから同じ持ち上げたコピーで直るはず。ただ、単位の終わりの規則が敷いた階の中の葉について規則が
  要り、それはこのパッチにふくまない。
- **行列を順序数として読むことは証明していない。** TRIO-ROW-3480-ja.md と同じく、順序、BMS 展開、
  yaBMS の標準形判定による較正にもとづく。
