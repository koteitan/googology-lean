# Fix U2: Fix U でもまだ間違っている規則 9 の修正

[`TrioFixU.lean`](TrioFixU.lean)（[koteitan/trio](https://github.com/koteitan/trio) の規則 1〜10 に
Fix A〜E, N, U を入れたもの）の上に重ねる別パッチ。コードは [`TrioFixU2.lean`](TrioFixU2.lean)、
検査は [`TrioFixU2Sheet.lean`](TrioFixU2Sheet.lean) にある。
マージするときは、1 ステップの中の `MpsiLevelU` を `MpsiLevelU2` に置き換える。

## 2 つの誤り

[TRIO-FIX-U-ja.md](TRIO-FIX-U-ja.md) の「未解決」には、規則 9 がまだ間違っている場所が 2 つある。

- **(a)** `u = Ω+k`、`w ≥ Ω_{Ω+1}` で、`w` の先頭が `ψ` でないとき。例: `ψ_{Ω_{Ω+2}}(Ω_{Ω_{Ω+1}+Ω_Ω})`。
  `M(w)` は標準形なのに、結果は標準形でない。
- **(b)** `u` のレベル `L` が有限で `L ≥ 2`、`Ω_Ω < w < Ω_u` のとき。`u = Ω_2+1` では、試した `w`
  のほとんどで結果が標準形でない。

記法は TRIO-FIX-U-ja.md と同じ。`w` は引数のレベル（`X = Ω_w`）、`M(v)` は `ψ_0(Ω_v)` の行列、
`base = low M(Ω_u)`、`P = M(ψ_{Ω_u}(Ω_{Ω_{L+1}}))`。

## 規則 9 の誤りと、受け継いだ誤り

規則 9 のパッチで直せるのは、規則 9 が `M(w)` に対してすることだけである。そこで各ラベルを
次の 3 つに分ける。標準形かどうかは yaBMS [`bms -s`](https://github.com/koteitan/yaBMS)、
ラベルの順序は `cmpOrd`、行列の順序は辞書式で調べる。

- **ok**: 結果が標準形で、同じ `u` のほかのラベルと順序が合う。
- **受け継ぎ**: ok でなく、`M(w)` 自身が標準形でないか、`M(w)` がほかの引数と順序が合わない。
  2 つの標準形の順序が合わないときは、そういう組を多く持つ方から責任を負わせる（貪欲法）。
  無実の引数に責任を負わせることもあるので、「受け継ぎ」の数は上界である。
- **規則 9 の誤り**: `M(w)` は ok なのに、結果が ok でない。

## 変更点

### 1. Fix K: `writeLevel` が、よその列をその場に残す

Fix E も Fix U も規則 9 を変えない所では、規則 9 は `base ++ writeLevel(M(w)) ++ 印` である。
`writeLevel` は、`M(w)` の尾部（梯子が覆う接頭辞のあとの列、規則 10）を、`x` を 1 つの量だけ
ずらして写す。尾部の列の中には、尾部がぶら下がる列とは別の接頭辞の列に、行 0 でぶら下がる
ものがある。典型は、前の階の錨にぶら下がる格上げの印（規則 5）である。ずらすと、その列は
親から離れてしまう。

`writeLevelK` は、そういう列の先祖の列が `base` の同じ位置にもあれば、その列を**そのまま**
（`x` も `y` も変えずに）写す。Fix U の `reroot` はすでにこの規則（「動かす部分にぶら下がって
いない列はそのまま写す」）に従っている。Fix K は同じ規則を `writeLevel` にも当てる。

例 (a): `u = Ω+2`、`w = Ω_{Ω+1}+Ω_Ω` のとき、`M(w)` の末尾は `(9,2,0)(2,2,1)(3,2,1)(4,1,0)` である。
印 `Ω_Ω` は階の錨 `(1,1,0)`（位置 7）にぶら下がり、`base` にも位置 7 に同じ列がある。

| | `M(ψ_{Ω_{Ω+2}}(Ω_{Ω_{Ω+1}+Ω_Ω}))` の末尾 | 標準形 |
|---|---|---|
| 規則 / Fix U | `… (12,2,0)(5,2,1)(6,2,1)(7,1,0)` | いいえ |
| Fix U2 | `… (12,2,0)(2,2,1)(3,2,1)(4,1,0)` | はい |

残る 2 つの反例も同じように変わる: `ψ_{Ω_{Ω+2}}(Ω_{Ω_{Ω+1}·Ω_Ω})` と、
`ψ_{Ω_{Ω+3}}(Ω_{Ω_{Ω+1}+Ω_Ω})`（`(6,3,1)(7,3,1)(8,1,0)` が `(2,2,1)(3,2,1)(4,1,0)` になる）。

### 2. ずらし行（`L ≥ 2`、`Ω_Ω < w ≤ Ω_{Ω_L}`）

このような `w` では `M(w) = M(Ω_Ω) ++ (1,1,0) ++ T` と書ける。このとき

```
M(ψ_{Ω_u}(Ω_w)) = P ++ (L+1,L+1,1)(L+2,L+1,1)(L+3,1,0) ++ T[x + L+2]
```

これは、Fix U の表にある引数 `Ω_Ω` の行列のあとに、`M(w)` の残りを続けたものである。残りは、
`M(w)` の列 `(1,1,0)` が `Ω` 葉 `(L+3,1,0)` に重なるように右へずらす。行 1 は変えない。
この行は Fix U の崩壊行より先に調べる。`L = 1` では範囲 `(Ω_Ω, Ω_{Ω_1}]` が空なので、この行は
何も足さない。

この形になる理由: `base = low M(Ω_u)` では、錨 `(L,L,0)` の下に兄弟の部分木
`(L+1,L+1,1)(L+2,L+1,1)(L+3,L+1,0)` と `(L+1,L+1,1)(L+2,L+1,1)(L+3,L,0) …` がある。`P` のあとで
この錨に新しい子を付けるなら、それはこれらの兄弟より大きくてはいけない。Fix U の持ち上げ
（`P ++ L'^L(M(w)[4:])`）は `(L+1,L+1,1)(L+2,L+1,1)(L+3,L+1,0)` で始まり、兄弟より大きいので、
決して標準形にならない。ずらし行は兄弟より下にとどまる。Fix U の `Ω_Ω` の葉 `(L+3,1,0)` で
始め、残りを全部その葉の下に置くからである。yaBMS の展開もこれに合う:
`P ++ (3,3,1)(4,3,1)(5,2,0)` の展開は
`P ++ (3,3,1)(4,3,1)(5,1,0)(6,2,1)(7,2,1)(8,2,0)(6,2,1)(7,2,1)(8,2,0)(6,2,0)…` であり、
これはずらし行で写した `Ω_{Ω_2}` から始まる。

例: `M(ψ_{Ω_{Ω_2+1}}(Ω_{Ω_Ω+1})) = P ++ (3,3,1)(4,3,1)(5,1,0)(6,2,1)(7,2,1)(8,2,0)(6,2,1)(7,2,1)(8,1,0)(7,2,0)(8,3,1)(9,3,1)(10,2,0)(9,3,0)(10,4,0)`
（標準形。Fix U では `… (10,2,0)(8,4,1)(9,4,1)(10,1,0)(9,4,0)…` で、標準形でない）。
Fix U は `ψ_{Ω_{Ω_2+1}}(Ω_{Ω_{Ω_2}})` を `P = ψ_{Ω_{Ω_2+1}}(Ω_{Ω_3})` より下に置いていた。
Fix U2 はそれを引数 `Ω_Ω` より上に置く。

### 3. `Ω_{Ω_L}` より上

`Ω_{Ω_L} < w < Ω_{Ω_L+1}` では、`M(w)` は `base` で始まる。ここでは、Fix K を入れた元の規則 9 が
Fix U の `reroot base P M(w)` に一致する。例えば `Ω_{Ω_2}+1` は `P ++ (9,4,0)(10,5,0)` になる。
これは `L = 1` での Fix U の行 `Ω_Ω < w < Ω_{Ω+1}` と同じ形である。`u = Ω_L+k` なら、範囲
`[Ω_{Ω_L+1}, Ω_u)` も Fix K で正しくなる。それ以外の `u`（`Ω_2+Ω+1`、`Ω_2·2+1`）では正しくない
（「未解決」を参照）。

## 定義域

`inDomainU2 u w` は、Fix U の `inDomain u w` であるか、次のすべてを満たすとき真になる:
`u` はレベル `L ≥ 2` が有限の非可算な後続順序数、`u ≤ w`、かつ（`u < Ω_L+ω` または
`w < Ω_{Ω_L+1}`）。Fix U の定義域はこれに含まれる（`inDomain_le_U2`）。

## 検査

検査用のラベルは、`u ≤ w < Ω_u` を満たす `ψ_{Ω_u}(Ω_w)` の 2,097 個である。その内訳は、Fix U の
1,865 個、レビューの 106 個、(a) と (b) のための新しい 126 個。`u` は `Ω+1` から `Ω_Ω+1` までの
15 個で、`Ω+4` も含む。

| 領域 | Fix U: ok / 受け継ぎ / 規則 9 の誤り | Fix U2: ok / 受け継ぎ / 規則 9 の誤り |
|---|---|---|
| (a) `u = Ω+k`、`w ≥ Ω_{Ω+1}`、先頭が `ψ` でない | 49 / 25 / **41** | 90 / 25 / **0** |
| (b) `L ≥ 2`、`Ω_Ω < w < Ω_u` | 39 / 232 / **570** | 641 / 178 / **22** |
| `L ≥ 2`、`w ≤ Ω_Ω` | 190 / 6 / 0 | 190 / 6 / 0 |
| `u = Ω+k`、それ以外の `w` | 243 / 6 / 0 | 243 / 6 / 0 |
| その他の `u`（主張しない） | 225 / 140 / 331 | 229 / 116 / 351 |

2,097 個全体:

| | Fix U | Fix U2 |
|---|---|---|
| 標準形でない | 1,258 | 664 |
| 順序が合わない組（同じ `u` の中） | 38,461 | 15,939 |

Fix U で標準形だったラベルが、Fix U2 で標準形でなくなることはない。唯一の例外は不正なラベル
`ψ_{Ω_{Ω_2}}(Ω_{Ω_{Ω_2}+1})` で、これは除いた。どの `u` でも、順序が合わない組の数は減るか
変わらない。「その他の `u`」で規則 9 の誤りが 331 から 351 に増えるのは、そこでの引数の一部
（入れ子の `ψ_{Ω_{Ω_2+1}}(…)` など）が ok になったためだけである。その結果、それらのラベルの誤りが
受け継ぎではなく規則 9 の誤りに数えられるようになった。

**主張する定義域。** 2,097 個のうち 1,559 個が `inDomainU2` に入る。そのうち 225 個は受け継いだ
誤りを持つ。残りの **1,334 個はすべて標準形（yaBMS）で、ラベルの順序と行列の順序が合い、
食い違いは 0** である。同じ `u` どうしの組でも、1,334 個全部をまとめて並べても成り立つ。
Lean（`TrioFixU2Sheet.lean` の Part 5）では、選んだ 784 ラベルを足しても並べた順の検査が通る。
Fix U の行列では通らない。

シートのファイルの検査には約 20 分かかる。このファイルはライブラリ `GoogologySheets` に属する。
マージするときは、`GoogologySheets.lean` に `import Googology.Trans.BMS.TrioFixU2Sheet` を、
本体のライブラリに `import Googology.Trans.BMS.TrioFixU2` を足す。

**変わらないもの。** Fix U2 は、シートのコーパスの 1,209 ラベル（Part 1）も、Fix U の定義域の
検査用ラベル 562 個（Part 2）も変えない。検査用ラベルのうち Fix U の定義域に入るものについて、
Fix U2 が変えるのはちょうど 48 個で、どれも (a) のラベルである。そのうち 41 個は標準形になる。
7 個は `M(w)` が標準形でないので、標準形でないまま残る（`+Ω_ω`、`·Ω_ω`、`+Ω_{ω²}`）。

**展開。** 定義域の中でずらし行を使うラベルについて、BM4 の展開と構成が可換か、つまり
`(M(w) の像)[n] = (M(w)[n]) の像` かを `n = 0, 1, 2` で調べた。1,698 件中 1,492 件で成り立つ。
成り立たない 206 件はどれも `n ≥ 1` で、どれも `M(w)` の悪い根が頭 `M(Ω_Ω) ++ (1,1,0)` の中
（列 0）にある。これは Fix U の持ち上げと同じ状況である（TRIO-FIX-U-ja.md を参照）。

## 証明したこと

[`TrioFixU2.lean`](TrioFixU2.lean) の中で、`sorry` なし、新しい公理なし、`native_decide` なし
（公理は多くとも `propext`、`Classical.choice`、`Quot.sound`）:

- `writeLevelK_false`: 残さない場合の `writeLevelK` は `writeLevel`（`arg = true`）に等しい。
- `MpsiLevelK_false`: 残さない場合の `MpsiLevelK` は `MpsiLevel2` に等しい。したがって Fix K が
  変えるのは、残した列だけである。
- `writeLevelK_size`: Fix K が書く列の数は `writeLevel` と同じ。
- `MstepU2_notPsi`: `α` が `ψ_{Ω_u}(X)` でなければ、1 ステップは `MstepAll` のものに等しい。
- `MstepU2_psi`: `α = ψ_{Ω_u}(X)` なら、1 ステップは `MpsiLevelU2` で、Fix U のそれは `MpsiLevelU`。
- `MpsiLevelU2_of_not`: `u ≤ Ω` のときと `u` が極限のとき、規則 9 は Fix U のもの、つまり
  `MpsiLevel3` に等しい。
- `MpsiLevelU2_of_countable_arg`: 引数が可算なら、規則 9 は Fix U のもの。
- `MpsiLevelU2_of_fixed`: ずらし行の外で、Fix E か Fix U が規則 9 を変える所では、Fix U2 は
  その行列をそのまま使う。
- `MstepU2_eq_MstepU`: Fix U2 が発火しなければ、1 ステップは Fix U のもの。
- `shiftRow_size`, `shiftRow_prefix`: ずらし行の列数は `P.size + 3 + (m.size − 8)` で、
  `P ++ (L+1,L+1,1)(L+2,L+1,1)(L+3,1,0)` で始まる。
- `WF3_trioRuleMatrixU2`: どの列も 3 行で、`z < 2`。
- `inDomain_le_U2`: Fix U の定義域は Fix U2 の定義域に含まれる。

標準形であることと順序については、何も証明していない。それらは上の数値検査である。

## 未解決

1. **受け継いだ誤り**（定義域の 225 ラベル）: `M(w)` 自身が標準形でないか、順序が合わない。
   例えば `M(Ω_{Ω+1}+Ω_ω)`、`M(Ω_{Ω+1}·Ω_ω)`、`M(Ω_{Ω+1}+Ω_{ω²})`、`M(Ω_{Ω·2}+1)`、
   `M(Ω_{ψ_1(Ω_2)}+1)`、`M(ψ_{Ω_{Ω+ω}}(…))`、`M(ψ_{Ω_{ψ_1(Ω_2)}}(…))` は標準形でない。
   `M(Ω_{Ω+1}^Ω)`、`M(Ω_{Ω+1}^{Ω_Ω})`、`M(Ω_{Ω+1}^{Ω_{Ω+1}})` は `M(Ω_{Ω+1}^2)` と衝突する。
   これらは和と積の分岐の誤りか、1 段下の規則 9 の誤りであって、この規則 9 の誤りではない。
2. **`L ≥ 2` で `u` が `Ω_L+k` の形でなく、`w ≥ Ω_{Ω_L+1}` のとき**（`u = Ω_2+Ω+1` と `Ω_2·2+1` で
   22 ラベル）: Fix U の未解決 1 の `L ≥ 2` 版で、定義域の外にある（シートの検査 `openB`）。
3. **レベル 1 で `u` が `Ω+k` でなく `w ≥ Ω_{Ω+1}` のとき**、**`u` のレベルが無限のとき**、
   **`u` が極限のとき**、**`u` が可算のとき**: TRIO-FIX-U-ja.md と同じ。レベルが無限の非可算な
   後続順序数 `u` では Fix K も働き、一部のラベルを直すが、何も主張しない。
4. **新しい行列を裏付けるシートの行はない。** 根拠は、標準形であること、順序、展開である。

Fix U で標準形だったのに Fix U2 で行列が変わるラベルは 59 個ある。どれも (b) にあり、`L ≥ 2` で
ある。例えば `ψ_{Ω_{Ω_2+1}}(Ω_{Ω_{Ω_2}})` や、崩壊の引数 `ψ_{Ω_{Ω_2}}(…)` である。これらは標準形
だったが、順序が合っていなかった。
